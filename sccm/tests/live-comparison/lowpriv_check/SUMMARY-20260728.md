## 2. ⚠ Both of the first two attempts were invalid — read this before re-running

**The output directory must be empty.** Re-running into a used directory does **not**
overwrite raw data: dlt appends a new load package beside the old ones and preprocess
reads every `.jsonl.gz` per table, so the previous run's rows are UNIONed into the new
graph. Measured on the first attempt today: **11 of 24 raw tables held rows from both
2026-07-23 and 2026-07-28.** Worse, a table the new run finds empty keeps only the OLD
rows, silently resurrecting infrastructure that no longer exists.

None of this is visible from outside — exit code 0, fresh `graph/` timestamps, a
plausibly larger graph. Only enumerating `sccm/_dlt_loads/` reveals it.

The numbers above come from a third run into freshly created directories
(`openhound-clean/`), verified to contain **zero** pre-2026-07-28 files.

**A `--clean` flag now exists** for exactly this (`openhound collect sccm <out> --clean`):
it removes `sccm/`, `graph/` and `lookup.duckdb`, keeping the timestamped per-run logs
and reports. Without it the collector now emits a WARNING naming the load-package count
and the oldest package's date.

Note `run-openhound-both.ps1` reuses its output directories, so it needs `--clean` added
before it is trusted again. The pre-existing OpenHound results were preserved to
`_baseline-20260723/` before this run.

## 4. Node / edge parity — what the raw diff numbers actually mean

Raw compare output (`openhound-clean/pe-on/compare-*.json`, A = OpenHound, B = CMBP):

| | count |
|---|---:|
| nodes only in OpenHound | 28 |
| nodes only in CMBP | 26 |
| edges only in OpenHound | 110 |
| edges only in CMBP | 122 |

Those look alarming and mostly are not. Three effects inflate them:

1. **Random-GUID node ids (by design).** 14 of the 26 CMBP-only nodes are random GUIDs —
   CMBP's possible client devices. OpenHound emits the *same* devices with deterministic
   ids, so every one counts as "different" on both sides. **76 of the 122 CMBP-only edges
   touch such a node**, i.e. they are the same edges hanging off a differently-identified
   endpoint.
2. **Kind-name mismatches (CMBP inconsistency).** CMBP emits `SameHostAs`,
   `LocalAdminRequired`, `CoerceAndRelayToSMB`, `CoerceAndRelayToMSSQL` unprefixed — and
   also `CoerceAndRelaytoSMB` (lowercase `t`, ×1) — where OpenHound emits
   `SCCM_SameHostAs`, `SCCM_LocalAdminRequired`, `SCCM_CoerceAndRelayToSMB`,
   `MSSQL_CoerceAndRelayToMSSQL`. Pairing them up:

   | CMBP | n | OpenHound | n |
   |---|---:|---|---:|
   | `SameHostAs` | 29 | `SCCM_SameHostAs` | 28 |
   | `LocalAdminRequired` | 11 | `SCCM_LocalAdminRequired` | 15 |
   | `CoerceAndRelayToSMB` (+`CoerceAndRelaytoSMB`) | 6 | `SCCM_CoerceAndRelayToSMB` | 7 |
   | `CoerceAndRelayToMSSQL` | 5 | `MSSQL_CoerceAndRelayToMSSQL` | 4 |

3. **Tier-D families CMBP fabricates and OpenHound deliberately does not.** Sixteen
   CMBP-only edge kinds appear **exactly once each** — `SCCM_FullAdministrator`,
   `SCCM_AllPermissions`, `SCCM_IsAssigned`, `SCCM_ApplicationAdministrator`,
   `SCCM_AssignSpecificPermissions`, `SCCM_HasMember`, `SCCM_Contains`,
   `SCCM_HasNetworkAccessAccount`, `SCCM_HasPrimaryUser`, `SCCM_HasCurrentUser`,
   `SCCM_HasADLastLogonUser`, `SCCM_HasStoredAccount`, `MSSQL_GetTGS`,
   `MSSQL_GetAdminTGS`, `MSSQL_LinkedAsAdmin`, `MSSQL_ServiceAccountFor`. These are the
   RBAC/service-account families that cannot be collected without AdminService/WMI
   (design spec §5, Tier D). CMBP templates them anyway at low privilege; OpenHound's
   absence here is the intended behaviour, not a gap.

## 5. Property parity — no new gaps; the two real clusters are already ticketed

Properties CMBP populates that OpenHound does not, by cluster:

- **Kind-name artifacts — not real.** Every "missing property" reported against
  `CoerceAndRelayToAdminService`, `CoerceAndRelayToMSSQL`, `CoerceAndRelayToSMB`,
  `LocalAdminRequired` and `SameHostAs` (`traversable`, `collectionSource`,
  `coercionVictim*`) is the comparer matching CMBP's unprefixed kind against an OpenHound
  kind that does not exist under that name. OpenHound populates all of them on the
  prefixed kinds. Ignore.
- **AD node properties — tracked in `ope-c141`.** `Base`/`Computer` lack `DNSHostName`,
  `SamAccountName`, `domain`; `User` lacks `SamAccountName`, `distinguishedName`; `Group`
  lacks `Domain`, `Enabled`, `IsDomainPrincipal`, `SamAccountName`, `Type`,
  `distinguishedName`. Deliberate today — OpenHound relies on SharpHound to supply AD
  node properties. `ope-c141` covers closing it.
- **SCCM node extras — tracked in `ope-fb99`.** `SCCM_ClientDevice` lacks `CN`,
  `DNSHostName`, `currentManagementPoint`, `currentManagementPointSID`,
  `distinguishedName`, `domain`, `objectClass`, `previousSMSID`,
  `previousSMSIDChangeDate`, `samAccountName`, `servicePrincipalName`.
  **`SCCM_Site.siteType` is also missing and may not be named in `ope-fb99` — check.**

OpenHound populates a set CMBP does not, chiefly the entity-panel edge help
(`composed`, `general`, `linuxAbuse`, `windowsAbuse`, `opsec`, `references`) on every
custom edge kind, plus `displayname` / `environmentid` / `last_seen` on nodes.

| removed | kept identical |
|---|---|
| `SCCM_HasClient` 14 → 0 | `SCCM_AssignAllPermissions` 15 |
| `SCCM_SameHostAs` 28 → 0 | `SCCM_LocalAdminRequired` 15 |
